# Orca Flow

中文敏捷看板与 **Orca 四角色机器人**工作流。源码仓库：<https://github.com/zhonghuaming/orca-flow>。

## 工作方式

```text
工作区 + 任务 + 目标 / 允许操作范围 / 验收标准 + 执行路线
                 ↓ 插件生成任务说明，尚未发送
已保存的准备记录 + UTF-8 任务说明文件 + 产品 Bot 名称与 ID
                 ↓ 你在产品 Bot 聊天中手动提交
产品协调 → 开发 → 测试（默认快速路线）
                 ↓ 核对执行结果，由你最终验收
```

**插件目前不支持一键发送或启动机器人。** 生成任务说明后，需要你打开对应机器人的聊天、粘贴完整说明并提交。插件不会自动打开指定聊天，也不会替你点击发送。

默认快速、标准路线都是“开发 → 测试”；轻量修改由开发自验，复杂变更为“架构 → 开发 → 测试”。产品负责协调，不单设执行阶段。涉及复杂或敏感操作时仍需必要的独立审查；确认可复现的测试失败后，同一次执行内最多两轮返工。外部操作结果未确认时先核对，不自动重试。

## 首次使用与手动提交

1. 在 Orca 打开目标项目，从侧栏打开 **Orca Flow**。默认跟随当前工作区；无法唯一匹配时请手动选择。手动选择后会固定目标，切换项目时不会丢失未提交的表单草稿。
2. 在“机器人”点击“发现本机机器人”。这只读取列表，不启动模型。将四角色绑定到四个不同的已有机器人，核对产品 Bot 的名称及 ID。所需机器人缺失或已暂停时无法准备任务说明，不会自动换用其他机器人。
3. 新建任务，从看板点击“准备此任务”；也可在“团队工作流”点击“准备任务说明草稿”并关联任务。核对工作区路径、分支、本次执行角色、允许操作范围、验收标准和路线，然后点击 **准备任务说明**。这一步不会发送消息或消耗模型额度。
4. 在“已准备的任务说明（尚未发送）”查看本次执行目标、产品 Bot 名称与 `bot:<id>`、任务说明原文和 UTF-8 文件路径。生成后，说明中保存的目标与角色不会跟随界面切换而变化。
5. 在 Orca 机器人列表找到上述名称及 ID，打开该产品 Bot 的聊天。用本机编辑器打开任务说明文件，全选复制完整原文并粘贴到聊天中；不要仅提交文件路径或摘要。目标、角色或路线已经变化时，不要提交旧说明，先核对原准备记录。
6. 复核允许操作范围后，**由你在聊天中点击提交**，才可能启动机器人并消耗模型额度。发送结果未确认，请先核对原聊天，避免重复发送。
7. 手动提交后，此处仍是准备记录，**不会自动导入执行记录，也不会自动验收**。请在 Orca 聊天、执行记录和任务中查看真实结果。已有历史执行可在插件“执行记录”点击“核对执行结果”；未自动找到时填写准确的 Orca 执行记录 ID，系统最多自动查找最近 100 条记录。核对完成后，仍需你复核证据并确认验收任务。

“打开工作区看板”只打开目标工作区的看板，**不会定位到具体卡片**。Flow 任务与工作区看板中的执行任务分别保存，尚无对应卡片时需手动核对。

仅支持本机工作区。产品 Bot 必须确认真实执行位置，不能只按说明中的路径推定执行目录；无法确认时应停止执行并说明原因。授权不包含生产操作、真实交易、破坏性数据库操作、凭据读取、权限扩大或对外发布，这些仍需具体授权。插件不创建额外机器人、不改机器人或工具权限、不查询额度。

## 记录保存与恢复

- **已生成任务说明，尚未发送**：准备不发送消息、不启动模型、不创建执行记录或执行任务，也不推进任务状态。准备记录不是执行或验收结果。
- 准备记录与已有执行记录分别保存。准备时保存目标工作区、路径、分支、项目、执行主机、角色、产品 Bot 名称与 ID、任务快照、目标、范围、路线、验收标准和说明原文，重载后可继续查看。
- 相同准备记录 ID 的内容发生变化时会拒绝覆盖。相同内容重复点击会复用原记录；同一任务已有不同说明时，不会覆盖或重复创建。更改目标或路线前请先核对已有记录。
- 最多保存 32 份准备记录，所有状态合计上限为 224 KiB；业务模板写入仍限 160 KiB。任务说明文件最多 32 份，包含存储失败后留下的待恢复文件。达到容量时会明确提示，不自动清理或归档。目前没有删除准备记录的入口，达到上限需另行安排保留原文的维护操作。
- 文件保存在本机 `~/.orca/flow-native/requests/`，以 `prepared-<id>.md` 独立创建，不覆盖原文。文件写入失败不会创建记录或推进任务；文件已写入但记录保存失败时，可用完全相同的请求重试，只有原文一致才会复用文件恢复。这里不是后台执行队列，没有程序自动发送这些文件。
- 工作区已有进行中或待核对的执行时，会阻止重复准备。这是为避免重复发送或执行，不是机器资源被占用；生成说明不会取消原执行。即使任务失败，发送结果仍未确认时也必须先核对，不能靠归档跳过核对。已有执行记录保持不变。
- 已有执行记录保留历史平台回执，但回执不等于模型已执行，也不代表后续阶段已收到任务。旧记录按原四阶段核对，新记录按本次路线所需阶段、前置任务和相同源码版本的结果证据核对。目标路径、分支、项目或执行主机变化时会拒绝核对，请先人工确认。
- 任务完成后仍需用户确认验收，不会自动完成迭代。已结束且发送结果已确认的记录可以归档：原始目标与完整证据保存在本机文件中，面板只保留精简记录；归档后仅供查阅，不能重新执行。关联任务已完成但尚未验收时，需先验收再归档。

## 本地开发与离线验证

不需要前端构建或网络依赖。需要已安装的 Orca、Node.js；类型检查另需本机 TypeScript。

```text
orca plugin types E:/workspace/orca-flow --json
node --test E:/workspace/orca-flow/tests/*.test.mjs
node --test --experimental-test-coverage E:/workspace/orca-flow/tests/*.test.mjs
orca plugin test E:/workspace/orca-flow --json
orca plugin check E:/workspace/orca-flow --json
orca plugin validate E:/workspace/orca-flow --json
tsc -p E:/workspace/orca-flow --noEmit
```

- `plugin test` 使用本地模拟宿主与命令，不发送真实任务。
- `plugin check` 的 `empty` 和 `populated` 场景只使用模拟工作区与内存存储，不运行真实 Orca 任务命令。
- `.orca/types` 由 Orca 生成，不应修改或提交。
- `artifacts/` 用于离线日志与截图，默认不提交，避免带出本机项目信息。
- `node --test` 的临时测试文件在系统临时目录创建并清理，不访问真实账号。

### 离线场景截图

窗口隐藏或最小化时，可使用离线场景截图，不触碰真实插件面板、存储或机器人：

```text
orca plugin shot E:/workspace/orca-flow --scenario populated --width 900 --out E:/workspace/orca-flow/artifacts/flow-wide.png --json
orca plugin shot E:/workspace/orca-flow --scenario populated --width 360 --out E:/workspace/orca-flow/artifacts/flow-narrow.png --json
```

### 加载与技术说明

`orca plugin dev load E:/workspace/orca-flow --json` 会显示插件访问授权，首次加载须由用户确认。权限标识为 `trusted-worker`、`storage:own`、`workspace:read`、`workspace:write`：插件后台程序以本机用户身份运行，这些声明不构成 Node 文件系统或进程沙箱。命令采用固定命令与参数数组，不经过 shell，设有超时，并清除继承的会话身份和远端选择环境。

当前支持的 Orca 1.4.279 未提供可供插件使用的机器人发送接口，因此旧 `flow.launch` 始终拒绝执行；`flow.prepare` 只生成任务说明。插件不借用其他会话身份、`--from` 或终端代发，不通过界面自动提交，也不会扩大权限。这些限制不会降低任务结果的核验要求。

Windows 默认使用当前安装的 `.../Programs/orca/resources/bin/orca.exe`；Orca 管理的环境优先使用 `ORCA_CLI_COMMAND`。其他系统默认 `/usr/local/bin/orca`，可由宿主环境提供准确的 `ORCA_CLI_COMMAND`，不要把它设置为 shell 命令串。

## 迁移边界

这是独立插件 ID `flow-native`、发布者 `zhonghuaming`，不会接管旧插件存储或复制旧账号信息。旧插件和保留的快照不变；迁移既有任务需要另行提供明确的导入流程，不会静默迁移凭据或改写已存任务。

旧版的账号隔离、供应商额度、自由 CLI flags、按终端状态推测成功、五角色示例团队、私有团队聊天脚本均已从当前运行源码移除。保留中文看板、迭代/史诗、任务关联、工作流目标与模板、工作区看板入口和执行结果查询。未保留原供应商的账号和磁盘使用统计。
